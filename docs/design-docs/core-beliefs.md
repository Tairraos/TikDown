# 核心信念（智能体优先的操作原则）

> 这是**争议的裁决依据**。当"该不该这么做"出现分歧时，回到这份文件，而不是回到聊天记录。

## 通用工程原则（方法论基线）

1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 工程师的工作是设计环境、明确意图、构建反馈回路。
3. 上下文是稀缺资源；给地图，不给说明书。
4. 智能体在运行时看不到的东西，对它来说不存在——一切进仓库。
5. 强制不变量，不微观管理实现；中央强制边界，本地允许自主表达。
6. 纠错成本低，等待成本高；短生命周期变更 + 最小阻塞式门禁。
7. 技术债是高息贷款，小额高频偿还。
8. 遇到卡点先问："缺的是什么能力？如何让它既清晰可读又可强制执行？"
9. 人类品味要持续被捕捉——写进文档，或直接编码进工具。
10. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。
11. 改造存量项目时，重构不改变业务行为；行为变更必须显式登记并单独提交。
12. 偏好无聊的技术：可组合、API 稳定、行为可推理的依赖优先。

## 本项目的第一性原则（产品与架构取舍）

13. **平台适配责任交给 yt-dlp 上游。** 平台改接口时只升级 yt-dlp，本项目代码一行不改。自研逆向 API 是已经死过一次的路（v1 因此不可用），绝不回头。
14. **"只下视频"的唯一机制是 yt-dlp 的 `--match-filter "vcodec!=none"`。** 不自己判断文件类型；探测阶段的图文判定只是把同一机制提前到任务创建时给用户反馈。
15. **组件（yt-dlp/ffmpeg）不进安装包。** 它们是月更的 25–40MB 大件，进包=把自动更新的东西做成静态包袱。按需下载到 `~/.tikdown`，且**每一级探测顺序（用户指定 > 应用副本 > 系统 PATH）都必须过版本门槛**——一个 2024 年的系统 yt-dlp 会让整个应用静默失效。
16. **不做静默自动下载。** Windows Defender 会隔离未签名二进制，macOS Gatekeeper 也会拦；必须用户主动点击、下载前告知体积与来源。
17. **ffmpeg 必须显式 `--ffmpeg-location`。** brew 版 yt-dlp 找不到系统 ffmpeg 时会静默不合并、退出码仍为 0、还打印一个不存在的合并路径——这是实测踩过的最深的坑。
18. **机器可读格式优先。** 进度用 `--progress-template`（tab 分隔），元数据用 `--dump-single-json`；永不解析 yt-dlp 的人类可读文案，上游改文案不应对我们产生任何影响。
19. **失败三分法。** 提取器问题→提示升级 yt-dlp；登录墙→引导开启 Cookie；网络问题→提示代理。笼统的"下载失败"是缺陷。
20. **Cookie 是用户授权行为。** 读取浏览器登录态必须用户显式开启，并给用户写清楚"如何获得 Cookie"的方法（浏览器直读 / cookies.txt 导入），需要登录时由用户自己在浏览器完成。
